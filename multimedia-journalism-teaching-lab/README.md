# Field Notes — Multimedia Journalism Teaching Lab

**Independent educational portfolio work sample | 2026 | Michael Farzinpour, PhD**

A self-contained, browser-based learning simulation for introductory multimedia journalism. Students work through five editorial decisions in a **fully fictional** community-water-advisory scenario, build a multimedia news draft, and review their work against a rubric.

## What is included

- `index.html`: the complete responsive site. No dependencies, accounts, external calls, or tracking.
- `INSTRUCTOR_GUIDE.md`: learning outcomes, 15-minute demonstration plan, 20–30-minute independent assignment, differentiation and accessibility notes.
- `ASSESSMENT_RUBRIC.md`: scoring rubric for story drafts, independent of multiple-choice responses.
- `sample_story.md`: an illustrative fictional student response (not a real news story).

## Local use

Open `index.html` in a modern browser. No build step required.

## Publish to GitHub Pages

Create a public repository (for example `multimedia-journalism-teaching-lab`) and upload the files from this folder to the repository root. In **Settings → Pages**, choose **Deploy from a branch**, select `main` and `/ (root)`, then save. GitHub Pages will publish the static site at a URL similar to `https://USERNAME.github.io/multimedia-journalism-teaching-lab/` after deployment. This URL is only an example; it is not live until you deploy.

To add this to an existing portfolio, link to the published Pages URL and label it **Independent Multimedia Journalism Teaching Lab — fictional teaching simulation**.

## Credibility and scope

All events, people, source statements, documents, and locations in the case are fictional. No claim is made that this is teaching work at Cuesta College or that any student learning outcomes have been empirically tested. The simulation demonstrates instructional design capability; it does **not** establish journalism-discipline minimum qualifications or equivalency.

## Accessibility and privacy

Uses semantic headings, grouped radio inputs, visible focus styles, clear feedback, reduced-motion support, keyboard-accessible controls, and responsive layouts. Text the student enters is held only in browser tab memory; nothing is sent to a server. Students may export a `.txt` draft. Accessibility has not been independently audited; conduct keyboard, screen-reader, and contrast testing before classroom adoption.
